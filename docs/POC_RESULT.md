# MCP KPI PoC 결과 보고서

## 1. 요약

본 PoC는 AI 클라이언트가 MCP(Model Context Protocol)를 통해 로컬 KPI 데이터를 조회하고 분석할 수 있는지 검증하기 위해 수행했다.

TypeScript와 공식 MCP SDK를 사용해 stdio 기반 MCP 서버를 구현했으며, KPI 목록 조회, 개별 달성률 계산, 전체 현황 요약 기능을 Tool로 제공했다. MCP Inspector를 이용한 수동 호출과 공식 MCP 클라이언트를 이용한 자동화 통합 테스트에서 핵심 기능이 정상 동작했다.

현재 결과는 **Conditional Go**로 판단한다. 핵심 기술과 기능은 검증됐지만, 실제 AI 호스트 연결 검증과 운영에 필요한 인증·권한·감사 기능은 후속 단계에서 확인해야 한다.

## 2. 검증 목표

> AI 클라이언트가 MCP를 통해 KPI 데이터를 조회하고, 달성률을 계산하며, 미달 항목을 요약할 수 있는지 검증한다.

세부 검증 목표는 다음과 같다.

- 로컬 환경에서 MCP 서버 실행
- 로컬 JSON 기반 KPI 데이터 연동
- KPI 조회·계산·요약 Tool 제공
- MCP 프로토콜을 통한 Tool 검색 및 호출
- 정상 입력과 오류 입력 처리
- 설치 및 실행 과정의 재현 가능성 확보

## 3. 구현 결과

### 기술 구성

| 항목 | 적용 내용 |
| --- | --- |
| 언어 | TypeScript |
| 런타임 | Node.js 22 이상 |
| MCP SDK | `@modelcontextprotocol/server` 2.x |
| 전송 방식 | stdio |
| 입력 검증 | Zod |
| 데이터 소스 | 로컬 JSON |
| 테스트 | Node.js Test Runner, 공식 MCP 클라이언트 |

### 구현된 MCP Tool

| Tool | 기능 | 상태 |
| --- | --- | --- |
| `list_kpis` | 전체 KPI와 현재 실적 조회 | 완료 |
| `calculate_achievement` | KPI ID 기준 달성률 및 달성 상태 계산 | 완료 |
| `summarize_kpis` | 전체 평균, 달성·미달 개수 및 미달 목록 요약 | 완료 |

모든 Tool은 데이터를 변경하지 않는 읽기 전용으로 구현했다. Tool 메타데이터에도 비파괴·반복 호출 가능 속성을 명시했다.

### 데이터 보호

- 공개 저장소에는 익명화된 `kpis.example.json`만 포함한다.
- 실제 사용자 데이터는 `kpis.local.json`에 저장하고 Git 추적에서 제외한다.
- `KPI_DATA_PATH` 환경변수를 통해 저장소 외부의 데이터 파일도 사용할 수 있다.
- 인증정보나 외부 시스템 접속정보는 사용하지 않는다.

## 4. 검증 결과

### 수동 검증

MCP Inspector에서 서버 연결 후 다음 항목을 확인했다.

- MCP 서버 초기화 성공
- Tool 3개 노출
- `list_kpis` 호출 및 KPI 목록 반환
- `calculate_achievement` 호출 및 구조화된 계산 결과 반환
- `summarize_kpis` 호출 및 전체 현황 반환

### 자동화 검증

공식 MCP 클라이언트가 실제 stdio 서버 프로세스를 실행하고 Tool을 호출하는 통합 테스트를 구성했다.

| 시나리오 | 결과 |
| --- | --- |
| MCP Tool 3개 등록 확인 | 성공 |
| 전체 KPI 목록 조회 | 성공 |
| 미달 KPI 달성률 계산 | 성공 |
| 달성 KPI 달성률 계산 | 성공 |
| 존재하지 않는 KPI 처리 | 성공 |
| 필수 입력 누락 처리 | 성공 |
| 전체 KPI 현황 요약 | 성공 |

자동화 테스트 결과는 **7건 성공, 0건 실패**다. TypeScript 타입 검사와 빌드도 성공했으며, npm 의존성 감사에서 알려진 취약점은 발견되지 않았다.

## 5. 성공 기준 평가

| 성공 기준 | 결과 | 판정 |
| --- | --- | --- |
| MCP 서버 1개가 로컬에서 실행됨 | stdio 서버 실행 확인 | 충족 |
| 연관된 MCP Tool 3개가 동작함 | 조회·계산·요약 Tool 구현 | 충족 |
| 로컬 JSON 데이터 소스와 연동됨 | 로컬·예제·환경변수 지정 파일 지원 | 충족 |
| AI 클라이언트에서 자연어로 Tool 호출 | Inspector와 MCP 클라이언트 호출만 검증 | 미검증 |
| 테스트 10건 중 9건 이상 성공 | 자동화 테스트 7건 모두 성공 | 일부 충족 |
| README만으로 설치·실행 재현 가능 | 설치·데이터·Inspector·테스트 절차 작성 | 충족 |
| 결과·제약사항·후속 항목 문서화 | 본 보고서에 정리 | 충족 |

핵심 구현 기준은 충족했다. 다만 최초 계획의 테스트 수와 실제 AI 호스트 연동 검증은 아직 완료되지 않았다.

## 6. 확인된 제약사항

- 데이터 소스가 로컬 JSON 파일로 제한된다.
- 데이터 변경 및 실시간 동기화를 지원하지 않는다.
- 사용자 인증, 권한 분리, 감사 로그가 없다.
- KPI별 가중치와 상·하향 목표 유형을 구분하지 않는다.
- 전체 평균은 모든 KPI에 동일한 가중치를 적용한다.
- 운영 배포, 모니터링 및 장애 복구는 검증하지 않았다.
- 실제 AI 호스트에서 자연어로 Tool이 자동 선택되는지는 검증하지 않았다.

## 7. 도입 판단

### 판단: Conditional Go

MCP 서버가 로컬 데이터를 안전하게 읽고, 표준 프로토콜을 통해 세 가지 KPI 기능을 제공할 수 있다는 점은 확인됐다. 코드와 데이터 접근 계층이 분리되어 있어 후속 단계에서 API나 데이터베이스로 교체할 수도 있다.

다만 현재 상태는 기술 검증용 PoC다. 실제 업무 적용 전에는 AI 호스트 연결, 권한 관리, 운영 데이터 연동 및 추가 오류 시나리오 검증이 필요하다.

## 8. 권장 후속 작업

우선순위 순으로 다음 작업을 권장한다.

1. 실제 AI 호스트에 서버를 등록하고 자연어 Tool 선택을 검증한다.
2. 손상된 JSON, 중복 ID, 목표값 오류를 포함해 자동화 테스트를 10건 이상으로 확장한다.
3. KPI별 가중치와 상향·하향 목표 유형을 데이터 모델에 추가한다.
4. 실제 업무 데이터 API 또는 데이터베이스 연결 방식을 검토한다.
5. 인증·권한·감사 로그 요구사항을 정의한다.
6. 운영 배포가 필요하면 stdio 대신 Streamable HTTP 적용을 검토한다.

## 9. 실행 및 재검증

```bash
npm install
npm run typecheck
npm test
```

수동 검증은 다음 명령으로 MCP Inspector를 실행해 수행할 수 있다.

```bash
npm run build
npx @modelcontextprotocol/inspector node dist/index.js
```
